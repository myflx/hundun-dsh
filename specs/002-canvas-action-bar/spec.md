## User Scenarios & Testing *(mandatory)*

### User Story 1 - 画布操作栏（缩小 / 重置 / 放大 / 刷新，Priority: P1）

画布打开时，底部显示操作栏，包含四个按钮，顺序与语义对齐 hundun-web 的 `canvas-controls` 工具栏：
**缩小 → 重置 → 放大 → 刷新**。右上角原有的独立缩放工具整合进该操作栏（不再重复出现）。
操作栏视觉与系统界面一致（同款背景、边框、圆角、悬停态），不遮挡画布内容。

**Why this priority**: 缩放与刷新是画布高频操作；当前缩放位于右上角浮层、无刷新入口；按 hundun-web 的
四按钮操作栏统一为画布控制入口，是用户明确指定的操作集合。

**Independent Test**: 打开画布 → 底部操作栏含四个按钮（缩小/重置/放大/刷新，顺序一致）→ 右上角无独立缩放工具
→ 缩小/放大以固定步进改变百分比 → 重置回 100% 与原点 → 刷新重新拉取工作区数据（工作区列表变化时画布同步）
→ 操作栏样式使用系统设计令牌。

**Acceptance Scenarios**:

1. **Given** 画布已打开, **When** 用户查看底部操作栏, **Then** 依次显示「缩小 / 重置 / 放大 / 刷新」四个按钮，右上角不再有独立缩放工具
2. **Given** 画布已缩放（如 110%）, **When** 用户点「重置」, **Then** 视图回到 100% 缩放且原点归位
3. **Given** 画布处于任一缩放级别, **When** 用户点「缩小」或「放大」, **Then** 缩放以固定步进（10%）变化并夹取在允许范围
4. **Given** 画布已打开, **When** 用户点「刷新」, **Then** 系统重新拉取工作区基线数据，画布随之更新（新增/移除的工作区反映到画布）；刷新失败不报错、画布保持原数据
5. **Given** 操作栏处于画布底部, **When** 用户拖拽卡片至操作栏附近, **Then** 操作栏不拦截拖拽、卡片可正常落位（低干扰浮层）
6. **Given** 画布打开, **When** 用户检查操作栏外观, **Then** 其背景/边框/圆角/悬停态与系统其他面板一致（复用系统设计令牌，无硬编码颜色）

---

### Edge Cases

- 画布极窄（操作栏空间不足）：四按钮紧凑排布（图标为主），不换行溢出
- 刷新请求失败/无刷新能力（workspaces 服务不可用）：安全降级（空操作或提示），画布数据保持原样
- 画布无工作区：操作栏仍显示（缩放/重置/刷新可用，仅无数据可刷）；不报错
- 重置视图时无任何平移/缩放（已是 100%/原点）：幂等，不产生多余写入
- 操作栏与右键菜单/明细面板同时出现：操作栏层级低于弹出层，弹出层不被遮挡

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在画布打开时于底部显示操作栏，按序包含「缩小 / 重置 / 放大 / 刷新」四个按钮（对齐 hundun-web `canvas-controls`）
- **FR-002**: 系统 MUST 移除右上角原有的独立缩放工具（整合后不重复出现）
- **FR-003**: 「缩小」/「放大」MUST 以固定步进（10%）改变缩放，并夹取在允许范围（沿用既有 30%–300%）
- **FR-004**: 「重置」MUST 将缩放恢复至 100% 并将平移原点归位
- **FR-005**: 「刷新」MUST 触发工作区基线重新拉取，画布随最新数据更新；刷新失败 MUST 安全降级（不报错、保持原数据）
- **FR-006**: 操作栏 MUST 复用系统设计令牌（背景/边框/圆角/悬停态/文字色），与系统其他界面控件视觉一致
- **FR-007**: 操作栏 MUST 为低干扰浮层：不拦截画布节点拖拽与空白平移交互，不遮挡可操作区域

### Key Entities *(include if feature involves data)*

- **CanvasDocument.view**: 视图变换（平移 x/y + 缩放 zoom），缩小/放大/重置读写该状态，随文档持久化
- **WorkspaceListState.items**: 工作区列表（官方 feed），「刷新」重新拉取后驱动画布更新

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户打开画布后能在 1 秒内定位到操作栏并完成一次缩放/重置/刷新操作
- **SC-002**: 「刷新」后画布反映最新工作区数据：新增工作区出现、移除工作区消失（在 feed 数据变化时验证）
- **SC-003**: 缩小/放大/重置/刷新 四按钮在操作栏中的顺序与 hundun-web 一致（缩小→重置→放大→刷新）
- **SC-004**: 操作栏视觉与系统控件一致：不引入任何非系统设计令牌的硬编码颜色/圆角/阴影（静态检查通过）
- **SC-005**: 以上操作全程零控制台错误；刷新失败不产生未处理异常

## Assumptions

- 「按照 hundun-web 画布的操作实现」指其 `canvas-controls` 工具栏的四个功能项：缩小（ZoomOut，步进 0.9）、
  重置（resetView：{x:0,y:0,zoom:1}）、放大（ZoomIn，步进 1.1）、刷新（重新拉取画布数据）；
  按钮顺序与图标语义对齐 hundun-web
- 缩放步进 10%（0.9/1.1 对应），夹取范围沿用既有 30%–300%（hundun-web 为 65%–180%，DSH 采用更宽范围
  以满足既有体验；步进与行为一致）
- 「刷新」在 DSH 中对应 workspaces 服务的基线重新拉取（`refresh()`，wire-pump 入口）；feed 更新后画布
  经订阅自动反映最新数据（新增/移除工作区）
- 「UI 与系统一致」指复用 dsh 系统设计令牌（`--dsw-alias-*` CSS 变量）与现有控件样式范式，不引入新设计语言
- 操作栏为画布内浮层（absolute 定位），不占用官方槽位，遵循既有面板互斥协议
- 依赖既有能力：视图变换（view-transform）、文档持久化（CanvasDocument.view）、画布挂载（CanvasController）、
  workspaces 服务（ctx.workspaces）
