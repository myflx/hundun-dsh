## User Scenarios & Testing *(mandatory)*

### User Story 1 - 分区域浏览工作区详情 (Priority: P1)

用户在画布中选中一张工作区卡片，右侧详情框以清晰的三块分区展示该工作区的完整信息：
**身份区**（顶行，大字号工作区名称 + 活跃状态徽标）→ **基本信息区**（目录、路径、
工作区 ID 键值对）→ **会话信息区**（会话数量表格：总数/活跃/归档/运行中）。
三块区域以卡片式视觉明显划分，用户扫一眼即可定位所需信息。

**Why this priority**: 分区域是「重新设计展示」的核心诉求——没有分区，语义化与 UI 渲染都无处安放；
这是本次功能的主体价值。

**Independent Test**: 选中任意工作区卡片后，详情框内能肉眼识别出 2 个分区
（身份 / 基本信息），每个分区的信息归属正确。

**Acceptance Scenarios**:

1. **Given** 画布中选中一张有标题的工作区，**When** 详情框打开，**Then** 详情框按
   身份区（无分区标题，大字号名称）→ 基本信息区两个分区渲染，基本信息区有区块标题
2. **Given** 详情框打开，**When** 用户滚动浏览，**Then** 各分区内容互不混淆，
   标签与值一一对应

---

### User Story 2 - 随机码的语义化展示 (Priority: P1)

工作区 ID（一串随机字符串）不再裸显示。当工作区没有自定义标题时，标题栏显示语义化占位
（如「未命名工作区」）而非裸 ID；基本信息区中 ID 以「工作区 ID」标签 + 值的键值对呈现，
并附一句人话说明（如「内部标识，用于区分工作区」），支持一键复制。

**Why this priority**: 用户明确点名「随机码（是id?）也要做好语义的描述」——
随机码即工作区 ID，本故事直接回答「它是什么、怎么友好呈现」的问题。

**Independent Test**: 选中一个无自定义标题的工作区（或标题为空），详情框标题栏
不出现裸随机码字符串；基本信息区以「工作区 ID」标签展示该字符串且可复制。

**Acceptance Scenarios**:

1. **Given** 工作区无自定义标题，**When** 详情框打开，**Then** 标题栏显示
   「未命名工作区」类语义占位，而非裸 ID
2. **Given** 详情框打开，**When** 用户查看基本信息区，**Then** ID 以
   「工作区 ID：<值>」键值对展示，并带一句说明文字
3. **Given** 详情框打开，**When** 用户点击 ID 的复制按钮，**Then** ID 完整复制
   到剪贴板且给出「已复制」反馈

---

### User Story 3 - 一致的键值对 UI 渲染 (Priority: P2)

详情框全部信息以统一的「标签 + 值」网格布局渲染：标签列（弱化色、固定语义）、
值列（主文字色、支持换行）。「最近活跃」等状态以高亮徽标呈现而非普通文本；
整体配色走系统令牌（背景分层、边框、三级文字色），拖拽调整宽度（240–420）时
布局不错乱、不溢出、不遮挡。

**Why this priority**: 「做好 UI 渲染」要求视觉一致性——键值对网格 + 令牌化样式
是让详情框在任意宽度下都稳定、美观的基础。

**Independent Test**: 打开详情框并把宽度从最小拖到最大，任意中间值下标签列对齐、
长值换行正常、无水平溢出、关闭按钮始终可见可点。

**Acceptance Scenarios**:

1. **Given** 详情框打开，**When** 用户调整宽度至 240–420 任意值，**Then** 键值对
   标签列保持对齐，长路径/长 ID 自动换行，无水平滚动条
2. **Given** 工作区为最近活跃，**When** 详情框打开，**Then** 「最近活跃」以
   高亮徽标（非纯文本）呈现
3. **Given** 详情框打开，**When** 用户查看任意区域，**Then** 文字颜色使用
   系统令牌分级（标题 primary / 标签 tertiary / 值 secondary），背景与边框
   与画布层级一致

---

### Edge Cases

- 工作区无自定义标题（label 缺失/为空）→ 标题栏用语义占位，不裸显示 ID
- 工作区 ID 很长（超过面板宽度）→ 值列换行展示，不横向溢出
- 路径为空或超长 → 显示语义占位（如「未知路径」）或安全换行
- 会话数为 0 → 显示「0 个会话」而非空白或「暂无」
- 宽度拖到最小（240）→ 标签与值不挤压重叠；拖到最大（420）→ 内容不拉伸变形
- 详情框内容总高超过面板可视高度 → 面板纵向滚动，分区标题可随内容滚动
- 复制 ID 时剪贴板被浏览器拒绝 → 降级为「自动全选文本」，仍可手动复制
- 工作区在 feed 中消失（刷新竞态）→ 详情框不崩溃、不残留

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 详情框 MUST 按「身份区 / 基本信息区 / 会话信息区」三块区域渲染，区块间
  有明显视觉划分（卡片式）；身份区展示大字号工作区名称（无分区标题）+ 活跃状态徽标；
  基本信息区含**目录 / 路径 / 工作区 ID** 键值对；会话信息区展示**会话数量表格**
  （总数 / 活跃 / 归档 / 运行中）
- **FR-002**: 工作区 ID MUST 以「工作区 ID」标签 + 值的键值对形式展示在**基本信息区**，
  并 MUST 附带一句语义说明文字（说明其含义），不得在任何位置裸显示随机码
- **FR-003**: 当工作区无自定义标题时，标题栏 MUST 显示语义化占位
  （如「未命名工作区」），不得回退为裸 ID
- **FR-004**: ID 值 MUST 提供一键复制操作，复制成功 MUST 给出「已复制」反馈；
  剪贴板被拒绝时 MUST 降级为全选文本
- **FR-005**: 全部信息项 MUST 使用统一的「标签 + 值」键值对布局，
  标签列样式一致（弱化色），值列支持长文本换行
- **FR-006**: 「最近活跃」状态 MUST 以高亮徽标/胶囊形式呈现，与普通文本可区分
- **FR-007**: 详情框样式 MUST 使用系统令牌（背景分层、边框、primary/secondary/tertiary
  文字色），不得使用与画布层级冲突的硬编码颜色
- **FR-008**: 面板宽度在 240–420 范围任意调整时 MUST 保持布局不溢出、不错乱、
  标签对齐；关闭按钮 MUST 始终可见可点
- **FR-009**: 会话数 MUST 以「N 个会话」可读格式展示（含 0 值）
- **FR-010**: 详情框内容超高时 MUST 支持纵向滚动，且关闭/宽度操作不受滚动影响
- **FR-011**: 基本信息区 MUST 以「目录」行展示工作区显示标题（缺失时回退路径文件夹名，
  再退「未知目录」），与「路径」「工作区 ID」行同为键值对布局
- **FR-012**: 会话信息区 MUST 以表格展示会话数量（总数 / 活跃 / 归档 / 运行中），
  与基本信息区（目录/路径/工作区 ID）分离，三块区域有明显视觉划分（卡片式）；
  会话数量计算在 sessions 服务不可得时 MUST 安全降级为 0（运行中），不抛错

### Key Entities *(include if feature involves data)*

- **Workspace（工作区）**: 画布中的基本单元，来自官方 workspaces feed。
  关键属性：`workspaceId`（随机字符串 ID，即「随机码」）、`title`（自定义标题，可缺失）、
  `path`（磁盘路径，可缺失）、`sessionIds`（会话 ID 列表）、`recentWorkspaceId`
  （全局最近活跃工作区标记，用于判定「最近活跃」状态）。
  详情框只读展示，不修改数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 详情框任意打开状态下，页面中不存在未带语义标签的裸随机码展示
  （100% 的 ID 出现处都带「工作区 ID」标签或说明）
- **SC-002**: 用户打开详情框后 5 秒内可识别出该工作区的身份信息
  （标题/占位、活跃状态）与位置信息（路径）
- **SC-003**: 详情框内肉眼可区分 2 个分区（身份区无标题 + 基本信息区带标题），
  分区信息归属正确（信息不错放分区）
- **SC-004**: 工作区 ID 复制操作 ≤1 次点击完成，且复制内容与显示值一致
- **SC-005**: 面板宽度在 240–420 范围内任意调整后，无水平溢出、标签不错位、
  关闭按钮始终可点（0 个布局回归）

## Assumptions

- 「随机码」即工作区 ID（`workspaceId`，官方 feed 数据的 `ref` 字段）；不做 ID 格式猜测
  （不解析其内部含义），只做「标注它是 ID + 说明用途」的语义化
- 详情框本次重设计范围仅针对**工作区节点**（kind=workspace）；编排节点/成员节点
  详情沿用现有扩展区块机制（registerNodeDetailSection），不在此次范围内改动
- 数据来源仅为官方 workspaces feed（title / path / sessionIds / recentWorkspaceId），
  不新增后端接口、不新增持久化字段
- 复制功能依赖浏览器剪贴板能力；失败时允许降级为全选文本
- 验证环境为本机 Windows / DSH web profile（HMR 开启），以 GUI 实际交互为准
- 「最近活跃」判定沿用现有 `workspaceId === recentWorkspaceId` 逻辑，本次不改语义
