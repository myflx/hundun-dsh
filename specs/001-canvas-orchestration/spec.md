## User Scenarios & Testing *(mandatory)*

### User Story 1 - 工作区总览与快速进入（Priority: P1）

用户打开画布视图，一屏看到全部工作区（标题 / 路径 / 会话数 / 最近活跃标记），点击任意工作区卡片直接进入该工作区的新会话；关闭画布后对话界面恢复原状。

**Why this priority**: 这是画布最基础、可独立交付的价值——把「逐个翻列表找工作区」变成「一屏总览 + 一步直达」，不依赖任何平台能力。

**Independent Test**: 打开画布 → 看到全部工作区卡片 → 点击一张 → 进入该工作区新会话 → 关闭画布 → 对话界面恢复且原对话状态保留。此流程独立成立即为可用 MVP。

**Acceptance Scenarios**:

1. **Given** 画布已打开, **When** 用户查看, **Then** 全部工作区以卡片呈现（标题 / 路径 / 会话数 / 最近活跃标记），数量与官方工作区列表一致
2. **Given** 画布已打开, **When** 用户点击某工作区卡片, **Then** 打开该工作区的新会话并退出画布
3. **Given** 画布已打开, **When** 用户点击侧边栏的会话/工作区行或「关闭」按钮, **Then** 画布退出，对话界面恢复且原对话状态保留

---

### User Story 2 - 布局持久化（Priority: P1）

用户按自己的心智模型拖拽摆放工作区卡片；刷新页面或重启后布局原样保留；数据异常时不崩溃。

**Why this priority**: 画布区别于普通列表的核心体验就是「空间记忆」，位置必须能留存，否则只是换了皮的列表。

**Independent Test**: 拖乱几张卡片 → 刷新 → 位置一致；写入坏数据 → 系统提示并正常启动。

**Acceptance Scenarios**:

1. **Given** 用户已拖动若干卡片位置, **When** 刷新页面或重新打开画布, **Then** 卡片位置与之前完全一致
2. **Given** 画布数据损坏, **When** 系统检测到, **Then** 不崩溃，提示用户并以空布局正常启动（原数据备份保留）

---

### User Story 3 - 编排画布平台：节点与连线（Priority: P1）

第三方插件可注册新的节点类型（外观 / 动作 / 明细）与连线规则；每个节点必须归属某个工作区（不允许「无家可归」的节点）；同工作区内的节点之间可连线，跨工作区默认禁止。

**Why this priority**: 这是画布从「视图」升级为「平台」的核心能力，也是聚合项目差异化的关键——让任务、主机、AI 预设等以节点形式共存于一个空间并表达关系。

**Independent Test**: 一个测试插件注册节点类型 → 节点出现在画布并可渲染 → 拖入工作区建立归属 → 同工作区两节点连线成功。

**Acceptance Scenarios**:

1. **Given** 某插件已注册节点类型, **When** 画布打开, **Then** 该类节点出现在画布上并按注册外观渲染
2. **Given** 一个新节点被创建, **When** 用户未为其指定工作区, **Then** 系统要求其先落入某工作区，无归属节点不可存在（显示提示而非静默丢弃）
3. **Given** 两节点同属一个工作区, **When** 用户拖线连接, **Then** 连接建立成功（同工作区内默认允许）
4. **Given** 两节点分属不同工作区, **When** 用户尝试跨区连线, **Then** 默认拒绝并给出原因；仅当规则显式允许跨区时方可

---

### User Story 4 - 工作区管理与可扩展右键操作（Priority: P2）

工作区卡片右键菜单提供「进入 / 重命名 / 删除 / 归档会话」；删除需确认并级联清理；其他插件可向任意节点类型追加右键动作。

**Why this priority**: 工作区管理是高频操作，动作可扩展是「操作开放给其他插件」的平台承诺；但不影响 MVP 的查看与进入。

**Independent Test**: 右键工作区 → 菜单出现内置动作 → 删除弹出确认 → 第三方注册动作后菜单新增该项。

**Acceptance Scenarios**:

1. **Given** 用户右键点击工作区卡片, **Then** 出现菜单：进入 / 重命名 / 删除 / 归档会话
2. **Given** 工作区下存在成员节点, **When** 用户选择删除, **Then** 弹出确认（列出将删除的成员数），确认后级联删除该工作区的全部成员节点与关系
3. **Given** 某插件注册了扩展动作, **When** 用户右键点击对应类型节点, **Then** 菜单中出现该扩展动作并可正常执行

---

### User Story 5 - 节点/工作区明细面板（Priority: P2）

点击节点或工作区时，画布右侧弹出明细面板；工作区明细含基础信息与会话数（不列会话条目，跳转侧边栏会话列表由既有能力承载）；其他插件可向任意节点类型追加明细区块。

**Why this priority**: 「点开看详情」是浏览编排空间的自然交互；可扩展区块让其他插件（如 SSH 主机状态）无需改画布即可贡献内容。

**Independent Test**: 点击工作区 → 右侧出现明细（基础信息 + 会话列表）→ 第三方注册区块后明细按顺序追加显示。

**Acceptance Scenarios**:

1. **Given** 用户点击某工作区卡片, **Then** 右侧弹出明细面板：标题 / 路径 / 会话数 / 最近活跃（不列会话条目；提供跳转侧边栏会话列表的入口）
2. **Given** 某插件注册了扩展明细区块, **When** 用户点击该类型节点, **Then** 明细面板按顺序渲染内置视图与扩展区块
3. **Given** 明细面板打开, **When** 用户点击空白处或「关闭」, **Then** 面板收起

---

### User Story 6 - 面板互斥（Priority: P2）

画布与任务看板、SSH 面板共享中间区域，同一时刻只显示一个；后打开者胜。

**Why this priority**: 多面板共存是聚合项目的必然场景，互斥保证界面不打架；协议已定稿，实现成本低。

**Independent Test**: 画布打开时打开 dsh-hello 改造的测试面板 → 画布让位；反之亦然。

**Acceptance Scenarios**:

1. **Given** 画布已打开, **When** 用户打开 dsh-hello 测试面板, **Then** 画布关闭，测试面板显示
2. **Given** dsh-hello 测试面板已打开, **When** 用户打开画布, **Then** 测试面板关闭，画布显示

---

### User Story 7 - 设置项：画布开关（Priority: P3）

设置面板新增「hundun-dsh」配置页（预留多栏目），「画布」栏目提供启用/关闭画布开关；关闭后画布入口、画布内容与系统公告一并消失，已保存布局保留。

**Why this priority**: 开关是配置能力而非核心功能，但「统一总开关语义」是设计定稿项，随 P0.5 一起落地。

**Independent Test**: 关闭开关 → 界面不再出现画布入口与内容 → 重新开启 → 恢复且布局保留。

**Acceptance Scenarios**:

1. **Given** 用户将画布开关设为关闭, **Then** 画布入口与画布内容不再出现（含系统公告）；**若画布此刻打开，立即关闭**，其他功能不受影响
2. **Given** 用户重新开启开关, **Then** 画布入口恢复，此前布局与数据保留

---

### User Story 8 - 视图浏览：缩放与平移（Priority: P3，未来阶段）

画布支持缩放（0.3x–3x）、平移、自动布局与对齐吸附，用户可自由浏览编排空间。

**Why this priority**: 工作区/节点增多后的浏览体验增强；设计已定稿（像素坐标 + 视图变换），实施依赖前序阶段完成。

**Independent Test**: 缩放平移流畅、新节点自动落位不重叠、拖拽有对齐参考。

**Acceptance Scenarios**:

1. **Given** 画布节点较多, **When** 用户滚轮缩放或空白拖拽平移, **Then** 视图流畅变换，缩放范围 0.3x–3x
2. **Given** 新节点加入, **When** 自动布局, **Then** 节点落位不与既有节点重叠
3. **Given** 用户拖动节点, **When** 接近对齐位置, **Then** 显示对齐参考线并可吸附

---

### Edge Cases

- 工作区从官方列表消失（被删除/移动）→ 画布提示并清理该工作区节点及其全部成员与关系
- 首次打开或没有工作区 → 空状态引导，不报错
- 画布数据损坏（JSON 解析失败）→ 备份原数据 → 以空布局启动并提示
- 节点插件卸载 → 该类节点显示「未知类型」占位，位置与关系保留，重装即恢复
- 拖动节点拖出所有工作区区域 → 无效操作并提示「请拖入目标工作区」，节点保持原位
- 删除含成员的工作区 → 确认提示列出成员数，防止误删
- 画布打开时点击侧边栏会话/工作区行 → 自动退出画布，对话优先
- 画布与其他面板并发打开 → 后打开者胜，不出现两个面板同时占用

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 侧边栏工作区搜索行 MUST 提供「画布视图」入口，用户可打开/关闭画布
- **FR-002**: 画布 MUST 呈现全部工作区（标题 / 路径 / 会话数 / 最近活跃标记），并与官方工作区列表实时保持一致（新增/删除自动反映）
- **FR-003**: 用户 MUST 能通过点击工作区卡片直接进入该工作区的新会话
- **FR-004**: 系统 MUST 持久化用户拖拽的工作区位置，刷新/重启后原样恢复
- **FR-005**: 用户 MUST 能退出画布（侧边栏行 / 关闭按钮），退出后对话界面恢复且原对话状态保留
- **FR-006**: 画布 MUST 与任务看板、SSH 面板互斥：同一时刻中间区域最多呈现一个面板，后打开者胜（验收对方面板 = 以 dsh-hello 改造的测试面板）
- **FR-007**: 第三方插件 MUST 能注册新的节点类型（外观 / 动作 / 明细视图）与连线规则，无需修改画布代码
- **FR-008**: 每个编排节点 MUST 归属且仅归属一个工作区；拖入工作区建立归属、拖到另一工作区迁移归属；无归属节点 MUST NOT 存在（提示用户而非静默丢弃）
- **FR-009**: 同工作区内的节点之间 MUST 能连线；跨工作区连线 MUST 默认禁止，仅当对应规则显式允许时方可
- **FR-010**: 工作区卡片 MUST 提供右键菜单：进入 / 重命名 / 删除 / 归档会话；删除 MUST 弹出确认（列出将删除的成员数）并级联清理该工作区全部成员与关系
- **FR-011**: 第三方插件 MUST 能向任意节点类型追加右键动作，与内置动作合并展示
- **FR-012**: 点击节点/工作区 MUST 在右侧弹出明细面板；工作区明细 MUST 含基础信息与会话数（不列会话条目）；第三方插件 MUST 能追加明细区块并按序展示
- **FR-013**: 数据异常时系统 MUST NOT 崩溃：节点插件卸载 → 占位显示且位置/关系保留；画布文档损坏 → 备份后以空布局启动并提示
- **FR-014**: 设置面板 MUST 提供「hundun-dsh」配置页（预留多栏目结构）；「画布」栏目 MUST 提供启用/关闭画布开关；关闭后画布入口、画布内容与系统公告 MUST 不再出现，**若画布正在打开 MUST 立即关闭**，已保存布局 MUST 保留
- **FR-015**: （未来阶段）画布 MUST 支持缩放（0.3x–3x）、平移、自动布局与对齐吸附

### Key Entities *(include if feature involves data)*

- **工作区（Workspace）**: 画布上的基底卡片，含标题 / 路径 / 会话数 / 最近活跃状态；是唯一容器——其他所有节点必须归属某个工作区
- **编排节点（Node）**: 第三方插件注册的卡片，含类型、外观、动作、明细；必须归属且仅归属一个工作区；业务数据留在插件域，画布只保存引用与位置
- **关系连线（Edge）**: 节点间的关联，含类型与两端节点；默认仅限同工作区内，跨工作区需规则显式允许；归属（属于哪个工作区）不是连线
- **画布布局（Layout）**: 全部节点的位置与视图状态；随用户会话持久保存，只含「引用 + 布局 + 关系」，不含业务数据
- **画布配置（Configuration）**: 「hundun-dsh」设置页下的画布栏目配置项（当前为启用/关闭开关），随设置持久保存

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 2 次点击内从画布进入任意工作区的新会话
- **SC-002**: 工作区数量 ≤ 100 时，打开画布、拖动卡片、切换面板均无明显卡顿（交互即时响应）
- **SC-003**: 用户自定义的布局在刷新/重启后 100% 恢复
- **SC-004**: 第三方插件无需修改画布代码即可完成「注册节点类型 → 渲染 → 建立归属 → 同区连线」全流程
- **SC-005**: 任何删除操作后不残留无主节点或失效关系（无游离态）
- **SC-006**: 关闭画布开关后，界面 100% 不再出现画布入口、画布内容与系统公告
- **SC-007**: 数据异常（文档损坏 / 插件卸载）时不崩溃，以明确提示或占位呈现，且不丢失业务数据
- **SC-008**: 面板互斥下，同一时刻中间区域最多呈现一个面板

## Assumptions

- 单用户、单浏览器使用；多人协作 / 跨设备实时同步不在范围内
- 画布只保存「引用 + 布局 + 关系」，不保存业务数据（业务数据归各插件与官方域）；卸载画布只丢布局不丢业务
- 工作区的新建 / 重命名 / 删除沿用宿主既有能力；画布不提供新建工作区
- 连线交互框架（US3 的连线部分）的实施以至少一个第三方插件承诺接入为前提（设计门槛 P1.4）
- 缩放 / 平移 / 自动布局 / 对齐（US8 / FR-015）为未来阶段，不在 MVP 验收范围
- 删除工作区 = 级联删除其成员节点与关系（成员不可脱离工作区存在），删除前必确认
- 项目章程（`.specify/memory/constitution.md`）当前为模板初始态、尚无生效原则；正式 ratify 后以其为准
